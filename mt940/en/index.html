What's inside the MT940 and DATEV files.

  1. MT940 (.sta), SWIFT format.

    :20: reference, :25: account, :28C: statement number, :60F:/:62F: opening and closing balance, :61: per entry with date, amount and debit/credit mark, :86: with a Geschäftsvorfallcode and the structured ?00-?34 subfields under the German SEPA convention (EREF+, SVWZ+). Lines capped at 65 characters and 6 lines, umlauts transliterated to the SWIFT X character set, CRLF line endings, one message per statement.

  2. DATEV-Format "Buchungsstapel" (EXTF CSV).

    A header row with the format identifier and the "Buchungsstapel" category, then the column-header row and one row per entry. Debit/credit follows the CdtDbtInd field from camt.053: a credit to the configured bank account becomes "Soll" (debit side in DATEV's convention), a debit becomes "Haben". DDMM dates, comma decimals, Windows-1252 encoding with umlauts intact.

Honest limits.

Not marketing copy, what to check before relying on this in production.

  • The exact wording of the :86: field varies by bank.

    There is no single Geschäftsvorfallcode convention identical across every institution. Check the result against a small test file before importing a full accounting period.

  • Two header metadata fields of the DATEV EXTF file are generic, not verified per-office.

    Enter your Beraternummer and Mandantennummer in the tool yourself; the header format follows publicly documented rules that are not individually confirmed for every DATEV version. A test import before production use is recommended.

  • Not a replacement for DATEV's Bankdatenservice.

    DATEV offers its own paid solution for a direct camt.053 upload. This tool is meant for the manual file import path and is not affiliated with DATEV.

  • MT940 is generated here, not fetched from your bank.

    If your bank now delivers only camt.053, this tool builds an MT940 file from it following the openly documented SWIFT field rules, for software that reads MT940 only.

FAQ

Why can't DATEV import camt.053?

Germany's banking industry (die deutsche Kreditwirtschaft) removed MT940 from its data-exchange rulebook in November 2025; many banks already deliver the statement as camt.053 only. DATEV Kanzlei-Rechnungswesen still has no direct import for camt.053 files, its manual file import still expects MT940. Sources: taxmain.de, a discussion thread in the DATEV community on the 23 November 2025 changeover deadline, and DATEV's own page on the new format, all read on 5 September 2026. DATEV offers its paid Bankdatenservice as a separate path for a direct camt.053 upload.

Is it safe to upload my account data here?

Nothing is uploaded. Parsing the camt.053 file and building MT940 or the DATEV Buchungsstapel file both run entirely in your browser, the tool has no backend that processes account data. The browser devtools network tab shows no request carrying the file content. The only network activity is loading the static page and an anonymous usage counter with no account data.

What does converting to MT940 or DATEV Buchungsstapel cost?

Converting camt.053 is free; without a licence the downloaded CSV or Excel file holds the first 20 rows as a sample. MT940 and DATEV Buchungsstapel export are Pro features: 9 euros a month or 79 euros a year, VAT included, billed through Stripe, one licence key valid across three ARLing bank tools (SEPA pain.001 Generator, camt.053 to Excel, Payment matcher).

What if my bank still offers MT940 directly?

Then you do not need this detour and can download the MT940 file directly from your online banking. Germany's banking industry removed MT940 from its rulebook industry-wide in November 2025; how quickly individual banks reflect that in their own online banking can vary during the transition. This tool is for the case where only camt.053 is left in your inbox.

Does this work with Sparkasse, Volksbank, Commerzbank, Deutsche Bank, UBS or PostFinance?

Yes. camt.053 is a bank-independent ISO 20022 format, the tool supports both common versions, camt.053.001.02 and camt.053.001.08, and detects the version automatically. It works with any bank in Germany, Austria or Switzerland that issues camt.053 as its statement, regardless of the bank's name.

Sources on MT940's removal and the DATEV import gap: taxmain.de/camt-053-in-mt940-umwandeln, DATEV community thread, datev.de, all read on 5 September 2026.
